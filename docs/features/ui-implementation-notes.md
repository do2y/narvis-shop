# 화면 구현 노트 — "이건 어떻게 만들었나"에 대한 답

> 그래프·차트·이미지·마크다운처럼 **눈에 보이는 것들이 실제로 어떻게 계산되는지**를 모은 문서.
> 아키텍처 3종(`architecture-*.md`)이 데이터 흐름이라면, 이쪽은 화면이다.
>
> 데모·발표에서 "그건 라이브러리 쓴 거예요?" 같은 질문이 나오는 자리를 골라 적었다.

## 0. 라이브러리를 쓰지 않은 것들 — 한눈에

| 화면 | 구현 | 라이브러리를 안 쓴 이유 |
|---|---|---|
| 취향 방사형 그래프 | **직접 SVG + 순수 함수 레이아웃** | 노드가 고정 구조라 force-directed 가 풀 문제가 없다 |
| 판매자 분석 차트 | **직접 SVG** | §2 |
| 마크다운 렌더 | **자체 파서** | §5 |
| 별점·리뷰 분포 | Tailwind 직접 구현 | 도메인 컴포넌트 원칙(CLAUDE.md) |

공통 판단: **넣어도 결과가 같은데 의존성만 느는 경우**엔 안 넣는다.
반대로 범용 부품(dialog·select·tabs)은 shadcn/ui 를 가져와 토큰에 맞춰 쓴다.

## 1. 취향 방사형 그래프 (mypage/preferences)

`나 → 관계 → 대상` **2단 구조**다.

> 대상끼리 잇는 링크가 데이터에 없어(모든 관계가 `나 → 대상` 한 방향·한 단계)
> 다단계 그래프는 만들 수 없다. 관계 5종이 **데이터에 실제로 있는 유일한 중간 단계**라
> 그것을 가지로 쓴다.

### 1.1 왜 d3-force 를 안 썼나

> 노드가 `나 1 + 관계 5 + 관계당 N`으로 **고정 구조**라 force-directed 가 풀 문제가 없다.
> d3-force 를 넣어도 결국 같은 그림이 나오는데 의존성만 는다.
> 나중에 물리 시뮬레이션이 필요해지면 **이 파일만** 갈아끼운다.

좌표 계산은 `graphLayout.ts` 에 **순수 함수로만** 뒀다(렌더 없음).
두 번째 이유가 검증이다 — 비례 배분·겹침 없음·빈 그룹 자리를 **렌더 없이 vitest 로** 확인한다.

### 1.2 각도 배분 — 균등하게 나누지 않는다

관계 5종을 72°씩 균등 분할하지 않고 **항목 수에 비례**해 나눈다.

> `avoids`·`purchased` 가 당분간 항상 비어 있어 두 방향이 텅 빈 채 남으면 화면이 어색해진다.
> 가진 만큼 차지하게 하면 그 비대칭이 "허전함"이 아니라
> **"내 취향이 이쪽에 몰려 있다"는 정보**가 된다.

가중치에 **제곱근**을 쓴다:

```ts
weight = Math.sqrt(n) + 1.4
```

> 개수를 그대로 쓰면 24 대 1에서 작은 쪽이 사라진다. 제곱근으로 눌러
> 편차는 보이되 작은 그룹도 라벨이 들어갈 자리를 갖게 한다.

**빈 그룹도 자리는 지킨다** — 지우면 "회피는 등록할 수 없나?"라는 오해가 생기고,
강조하면 오류처럼 보인다. 아래쪽(6시) 좁은 띠에 모으되, 개수에 비례해 늘린다
(4개가 62° 를 나눠 가지면 "아직 없어요" 라벨이 포개진다 — 하나당 34° 확보).

데이터가 있는 그룹은 **위·양옆**(눈이 먼저 가는 자리), 빈 그룹은 아래.
12시를 중심으로 좌우 대칭이 되게 시작 커서를 잡는다.

### 1.3 겹침 해결 — 각도로는 안 된다

**이 그래프에서 가장 많이 손본 부분.**

처음엔 부채꼴 각도만으로 간격을 잡았는데 라벨이 겹쳤다.

> **각도만으로는 간격을 보장할 수 없다.** 같은 26°라도 부채꼴의 어디에 놓이느냐에 따라
> 실제 세로 거리가 달라지고(양 끝으로 갈수록 sin 변화가 작아진다), `Y_SQUASH` 가
> 세로를 한 번 더 누른다. 그래서 각도를 아무리 키워도 라벨이 붙는 구간이 남는다 —
> 실측에서 6개(기본 상한)에서도 겹쳤다.

해결: 각도 계산 **후에 y 를 픽셀로 보정**한다.

```
1. 각도로 배치
2. y 정렬 → 최소 간격(21px) 못 채운 항목을 아래로 밀기
3. 밀린 만큼 원래 범위 중심으로 되돌리기
4. 뷰박스를 넘으면 통째로 밀고, 그래도 넘치면 간격을 균등 축소
```

**x 는 건드리지 않는다** — 가지에서 뻗어 나온 방향이 흐트러지면 어느 가지 소속인지 안 읽힌다.
라벨은 가로로 뻗는 한 줄이라 **세로로만 벌어지면 안 겹친다.**

3번의 "원래 범위 중심"이 포인트다. 가지 중심으로 당기면:

> 부채꼴이 원래 그 위나 아래에 놓였을 때 통째로 끌려와 그래프가 세로로 쪼그라든다
> (실측: 화면 세로 사용률 0.47까지 떨어져 "충분히 채운다" 테스트가 걸렸다).

### 1.4 뷰박스가 1200×680인 이유 (정사각형이 아니다)

**라벨이 가로로 길기 때문이다.** 정사각으로 두면 좌우 항목 라벨("블루투스 이어폰")이
잘리고, 그걸 피하려고 반지름을 줄이면 그래프가 한가운데 작게 뭉친다.

세로는 800 → **680** 으로 낮췄다:

> 패널이 가로로 넓고 세로는 뷰포트에 맞춰 잘리므로(약 1150×460, 2.5:1), 뷰박스가 3:2 면
> `preserveAspectRatio` 가 세로에 맞춰 축소해 **가로 814px 만 쓰고 좌우가 letterbox 로 남았다**
> (실측: 컨테이너 대비 64%).

완전히 2.5:1 로 맞추지는 않는다 — 세로가 눌리면 위아래 가지 라벨이 가까워지고,
세로 간격 보정이 그만큼 더 밀어내야 해서 부채꼴이 흐트러진다.

`Y_SQUASH = 0.72` 로 **타원 배치**하는 것도 같은 이유다. 원으로 두면 세로로도 반지름만큼
퍼져 뷰박스 위아래가 남는다.

### 1.5 반지름이 가지 수에 반응한다

고정하면 가지가 적을 때 **화면 한가운데 작게 뭉친다**(실측: 1가지에서 가로의 33%만 사용).

| 가지 수 | 중심→관계 | 관계→항목 |
|---|---|---|
| 1개 | 330 | 190 |
| 2개 | 300 | 190 |
| 3개+ | 286 | 165 |
| 포커스 모드 | 210 | 130 |

상한은 **라벨**이다 — 반지름을 키우면 바깥 라벨이 뷰박스를 넘는다.
가장자리에 라벨 폭(약 150px)이 남도록 잡았다.

한때 가지가 적을 때 중심을 왼쪽으로 밀었는데, 가지를 눕히는 보정과 겹쳐
**왼쪽 절반이 통째로 비는** 화면이 됐다. 지금은 반지름이 반응하므로 중심은 고정이다.

### 1.6 `Math.random()` 을 쓰지 않는다 — 결정적 해시

부채꼴이 컴퍼스로 그린 호처럼 보이는 걸 완화하려고 반경에 ±7% 변화를 준다.
그런데 무작위를 쓰면:

> 렌더할 때마다 자리가 바뀌면 같은 데이터인데 다른 그림이 되고,
> **수정 한 번에 화면이 통째로 흔들린다.**

그래서 `edgeId` 에서 뽑은 **FNV-1a 해시**를 쓴다. 같은 항목은 언제나 같은 자리,
항목이 바뀔 때만 그 항목의 자리가 바뀐다. 암호학적 강도가 필요 없는 자리라 짧고 빠른 걸로 충분.

### 1.7 표시 상한이 2개인 이유

| 상수 | 값 | 근거 |
|---|---|---|
| `GRAPH_ITEMS_PER_BRANCH` | 6 | 방사형에서 라벨이 안 겹치는 각도 한계 |
| `GRAPH_ITEMS_FOCUSED` | 24 | **뷰박스를 넘는가**로 정함 |

포커스 모드 값은 실측표로 정했다:

| 개수 | 겹침 | 화면 밖 | 세로 사용 |
|---|---|---|---|
| 24 | 0쌍 | 0개 | 483px |
| 28 | 0쌍 | 0개 | 567px |
| 32 | 0쌍 | **1개** | 651px |
| 40 | 0쌍 | 5개 | 819px |

28이 마지막 안전값이지만 **24를 쓴다** — 여유 4개가 있어야 라벨이 길어지거나
뷰박스가 바뀌어도 곧바로 깨지지 않는다.

**상한은 접기가 아니라 잘라내는 것**이고, 넘친 만큼은 `+N` 으로 알린다.
목록 뷰의 상한과 값이 다른 건 제약이 달라서다 — 목록은 세로로 무한히 늘어난다.

### 1.8 정렬은 서버 것을 지킨다

그룹의 **화면 배치만** FE 가 정하고, 그룹 **안** 항목 순서는 서버 것을 그대로 둔다.
앞에서부터 자를 뿐 재정렬하지 않는다.

그리고 반환 순서는 화면 배치 순서가 아니라 **계약 순서**로 되돌린다:

> DOM 순서가 곧 탭 순서라, 시각 배치를 따라가면 **키보드 이동이 뒤죽박죽**이 된다.

## 2. 판매자 분석 차트 (`AnalysisChart.tsx`)

**차트 라이브러리 없이 인라인 SVG로 직접 구현.** line / bar 2종.

대시보드(`SellerAnalysis`)와 챗 리포트(`SellerReportChart`)가 **같은 컴포넌트**를 쓴다 —
형태가 같아서 무수정으로 둘 다 받는다(계약 타입이 shared 에 있는 이유는 `shared → features`
역참조 금지 때문).

### 좌표계는 고정, 실제 크기는 CSS 가 정한다

```
viewBox 600×200, preserveAspectRatio="none"
```

`none` 을 쓴 이유가 비직관적이다:

> 기본값(비율 유지)이면 컨테이너가 528px 를 넘는 순간 **그림만 528px 에 고정돼 가운데
> 정렬되는데, x축 라벨은 컨테이너 폭 기준으로 절대 배치돼 둘이 어긋난다.**

대신 스케일이 **비균등**해지므로 선·점은 `non-scaling` 처리가 필요하다
(안 하면 가로로 늘어난 만큼 선 굵기도 늘어난다).

### y축은 항상 0을 포함한다

```ts
const min = Math.min(0, ...points.map(p => p.y));
const span = max - min || 1;      // 전 구간 동일값이면 0 division
```

0을 빼면 작은 변동이 절벽처럼 보인다. `|| 1` 은 모든 값이 같을 때의 방어.

### 점이 1개면 가운데

```ts
points.length === 1 ? innerW / 2 : (innerW * i) / (points.length - 1)
```

안 하면 `i / 0` 으로 `NaN` 이 나와 SVG path 가 통째로 깨진다.

### x축 라벨은 솎아낸다

리포트 차트는 한 달치(31점)가 오는데 전부 찍으면 글자가 겹쳐 읽을 수 없다 →
**최대 10개**로 균등 간격 샘플링(대시보드 7점은 그대로 다 나온다).

### 비균등 스케일의 대가를 3곳에서 갚는다

`preserveAspectRatio="none"` 은 가로/세로 스케일을 다르게 만든다. 그대로 두면 도형이 찌그러진다:

| 요소 | 증상 | 처리 |
|---|---|---|
| 선 | 굵기가 가로로만 늘어난다 | `vectorEffect="non-scaling-stroke"` |
| 막대 모서리 | `rx` 가 가로로만 늘어나 찌그러진다 | **`rx` 를 아예 안 쓴다** |
| 끝점 마커 | `circle` 이 타원이 된다 | **`r="0.01"` + `strokeWidth="8"`** |

마지막 트릭이 재밌다 — 반지름을 0에 가깝게 두고 **채움을 stroke 로 옮겨**
`non-scaling-stroke` 가 원형을 지키게 한다.

### 집계 방식은 서버가 알려준다 (추측 금지)

```ts
const aggregate = "aggregate" in analysis ? analysis.aggregate : "sum";
```

| aggregate | 헤더 숫자 |
|---|---|
| `sum` | 합계 |
| `avg` | 평균 |
| `none` | **표시하지 않음** |

> 평점 차트에 "합계 61.4점"을 찍으면 무의미하고, 가격·재고는 현재 시점 스냅샷이라
> 합계도 평균도 뜻이 없다.

**`unit` 으로 추측하면 안 된다** — 같은 `COUNT` 라도 판매 수량은 `sum`, 재고는 `none` 이다.
대시보드 타입엔 `aggregate` 가 없어 `in` 연산자 narrowing 으로 `sum` 폴백.

`RATING` 은 **소수 1자리 고정** — `4` 와 `4.0` 이 섞이면 열이 흔들린다.

### x축 라벨은 SVG 밖에 절대 배치한다

```tsx
style={{ left: `${(x(i) / W) * 100}%` }}   // SVG와 같은 x를 쓰므로 항상 정렬
```

> `justify-between` 은 솎아낸 뒤 남은 라벨을 **균등 분배해 버려서** 실제 데이터 위치와 어긋난다.

상품명 라벨은 길어서 `max-w-20 truncate` + `title` 로 전체 이름을 hover 노출한다.

### ⚠️ 접근성 — 주석과 구현이 어긋나 있다

주석은 "값은 표로도 함께 노출한다(스크린리더·색 구분 불가 사용자)"라고 적혀 있지만,
**실제 구현엔 대체 `<table>` 이 없다.** 현재는 `role="img"` + `aria-label`(차트 종류만) 한 줄뿐이고,
텍스트로 읽히는 값은 헤더의 합계/평균과 `summary` 문장뿐이다.

→ **개선 여지로 남아 있는 지점.** 데이터 포인트 값 자체는 스크린리더에 노출되지 않는다.

### `compact` · `bare` 두 플래그의 근거

| 플래그 | 왜 |
|---|---|
| `compact` | 대시보드는 차트 아래로 「오늘 할 일」이 이어지는데, 기본 높이면 **첫 화면이 차트로 다 차서 아래에 뭐가 있는지 안 보인다** |
| `bare` | 대시보드는 바깥에서 이미 섹션을 나눠 놨다 — 또 테두리를 그리면 **상자 안의 상자**가 된다 |

`useId()` 로 그라데이션 id 를 만든다 — 한 화면에 차트가 여러 개면 id 가 충돌해
**뒤 차트의 그라데이션이 앞 것을 덮어쓴다.**

## 2-1. PDF 내보내기 — 라이브러리 없이 브라우저 인쇄로

분석 리포트는 **스트림 1회성이라 새로고침하면 사라진다**(복원 API 없음).
남기려면 사용자가 직접 저장해야 한다.

### PDF 라이브러리를 안 쓴 이유

> 파일을 만들지 않고 브라우저 인쇄를 띄운다: 사용자가 "PDF로 저장"을 고르면
> **화면과 같은 폰트·차트(SVG)로** 출력된다. PDF 라이브러리를 쓰면 **한글 폰트를
> 통째로 임베딩(수 MB)** 해야 하고 레이아웃을 좌표로 다시 짜야 한다.

### `printElement` — body 직계로 복제해 꺼낸다

> 인쇄 대상이 flex·overflow 컨테이너 안쪽 깊숙이 있으면, **조상들이 높이를 가둬
> 내용이 첫 페이지에서 잘린다.** "대상만 남기고 조상 스타일을 되돌리는" 방식은
> 조상 사슬을 전부 풀어야 하고 하나만 놓쳐도 잘리므로, **아예 body 직계로 꺼내는 편이
> 예측 가능하다.**

`cloneNode(true)` 를 쓰는 이유:

> 라이브 노드를 옮기면 화면에서 사라졌다가 돌아와 **리액트의 DOM 소유권과 충돌한다.**
> 복제본은 리액트가 모르는 노드라 안전하다.

정리는 2중이다 — `afterprint` 는 인쇄·취소 양쪽에서 오지만 **일부 브라우저가 누락**하므로
`print()` 반환 뒤에도 한 번 더 정리한다(중복 호출은 무해).

### 인쇄 CSS 4규칙 (`globals.css`)

```css
body > *:not([data-print-portal]) { display: none !important }  /* 포털만 남긴다 */
[data-print-hide] { display: none }        /* 버튼·토글 제거 */
[data-print-body] { display: block !important }  /* 접힌 본문 강제 펼침 */
section { break-inside: avoid; box-shadow: none }  /* 절이 갈리지 않게 */
```

세 번째 때문에 React 쪽이 **조건부 렌더 대신 `hidden` 클래스**를 쓴다:

> 접힌 상태에서도 DOM 에 둔다 — 인쇄 CSS 가 펼쳐야 하는데 **조건부 렌더면 아예 없어서
> 되살릴 수가 없다.**

## 2-2. 인터랙션 상수 (`seller/interaction.ts`)

> 원래는 같은 성격의 버튼이 자리마다 press 세기(0.99·0.95·0.90)와 transition 대상이
> 제각각이었다. **개별 화면에서 눈으로 맞추면 다음 화면을 고칠 때 또 어긋나므로** 상수로 둔다.

규칙 4개가 전부 의도적이다:

| 규칙 | 이유 |
|---|---|
| **`transition-all` 금지** | `all` 은 shadow·layout 까지 잡아 불필요한 리페인트를 만든다 |
| `ease-out-strong` 사용 | CSS 기본 곡선은 완만해 반응이 잘 안 읽힌다. **`ease-in` 계열은 첫 순간을 비운다** |
| hover 는 `@media(hover:hover)` 뒤로 | 터치에서 탭이 hover 로 잡혀 **손을 뗀 뒤에도 배경색이 남는다** |
| 150ms 고정 | press 피드백은 "눌렀다"만 전하면 된다 — 길면 굼떠 보인다 |

`pressable`(0.97) 과 `pressableCard`(0.99) 를 나눈 이유:
**면적이 넓으면 같은 배율도 더 크게 읽힌다.**

### `prefers-reduced-motion` — 모션을 다 끄지 않는다

```ts
"motion-reduce:transition-none motion-reduce:active:scale-100"
```

> 축소 모션은 "모션 없음"이 아니라 **전정기관을 건드리는 움직임만** 빼는 것이다 —
> 색·불투명도 변화는 **상태를 알리는 정보**라 유지한다.

이동만 끄고 색 전환은 남긴다.

## 2-3. 판매자 대시보드 — 타이포·레이아웃 판단

### 금액은 자릿수가 예측되지 않는다 → `clamp`

```css
text-[clamp(1.875rem,5.5vw,3rem)]
```

> 백만원(9자)에 맞춰 48px 로 고정하면 **십억원(13자)에서 칸을 넘는다.**
> 좁은 화면일수록 먼저 줄여 두는 편이 안전하다.

**`break-all` 로 강제로 꺾지 않는 이유:**

> 숫자는 공백이 없어 줄바꿈이 안 된다. **금액이 중간에서 잘리면 자릿수를 잘못 읽는다** —
> 줄이 넘치느니 글자가 작아지는 편이 정확하다.

하한 30px 은 보조 지표(24px)보다 확실히 커서 **히어로 자리를 지킨다.**
`min-w-0` 도 필요하다 — flex 자식의 기본 `min-width:auto` 를 풀어야 실제로 줄어든다.

### 테두리를 걷어낸 이유

> 화면에 같은 테두리 상자가 9개였다. **테두리가 반복되면 무엇이 중요한지 말해주지 못한다** —
> 구분은 여백과 구분선이 대신한다.

"히어로 1 + 보조 3" 구조로 무게를 갈랐다. 구분선도 반응형이다
(모바일은 위쪽 선 `border-t`, 넓어지면 왼쪽 선 `lg:border-l`).

### 증감률은 3-state

```ts
// undefined = 줄 숨김 / null = 비교 데이터 없음("—") / number = 정상 증감률
const hasRate = m.deltaRate !== undefined;   // null은 "표시"에 포함
```

증감률이 없는 지표(실시간 방문자)도 **캡션은 남긴다** —
"최근 30분"이 빠지면 그 숫자가 무엇의 값인지 알 수 없다.

### 가드 하나가 곧 에러 처리

> 집계 실패로 블록이 null 이면 카드가 빠지고 그리드 첫 칸이 사라지며
> **차트가 자동으로 전폭이 된다. 별도 에러 UI 불필요.**

### 등록 초안 카드 — 상태 머신 하나로 몬다

```ts
// 순서가 우선순위다: 확정 결과 > 스트림 오류 > 처리 중 > 검토 가능
const state = settled ? (failed ? "error" : "done")
            : streamError ? "error" : disabled ? "busy" : "review";
```

배지·푸터·본문 흐림이 전부 이 값을 따른다.

- **확정 후 본문을 지우지 않고 흐린다** — 무엇을 등록했는지는 계속 보여야 한다
- **푸터는 sticky** — 설명이 길면 버튼이 스크롤 위로 밀려 "확인했으니 누른다"는 순서가 깨진다
- **`warning` 섹션만 기본 펼침** — "카테고리는 등록 후 변경할 수 없습니다" 같은
  되돌릴 수 없는 내용이 여기 들어가므로 접어두면 안 된다

### ⚠️ 계약 타입은 `string | number` 지만 실측은 문자열이다

> `typeof v === "number"` 로만 분기하면 **실제 와이어에서 한 번도 타지 않아
> 60000원이 "60000"으로 그대로 나온다.** 숫자로 파싱해서 판정한다.

`DraftReviewFields` 는 고쳤지만 **`ProductDiffCard.formatValue` 는 아직 옛 방식**이다.

### 값을 FE가 지어내지 않는다

정가와 판매가를 나란히 두되 **할인율(%)은 계산하지 않는다** —
FE 가 계산하면 AI 가 아는 값과 어긋나는 날이 온다.
`priceText`·`stockText` 는 서버가 포맷을 마쳤으므로 **콤마·단위를 다시 붙이지 않는다.**

빈 상태도 "없음"과 "오류"를 구분한다 — 필수값 누락은 **경고 톤**(등록 후에 알아채면 늦다),
이미지 없음은 정상이라 한 줄 안내로 끝낸다(**큰 회색 사각형을 띄우면 "빠졌다"로 읽혀
없는 문제를 만든다**).

## 3. 마크다운 — 라이브러리 대신 자체 파서 (`markdown.ts`)

LLM 이 만든 문자열을 렌더 가능한 블록으로 쪼갠다. 취향 요약(M-11)과 챗 말풍선(CH-2)이 함께 쓴다.

### ⚠️ 입력은 전부 신뢰 경계 밖이다

> 요약은 LLM 이 만든 문장이고, 챗 토큰에는 그에 더해 **사용자 발화와 판매자가 등록한
> 상품·옵션명이 그대로 실린다.** AI 가 쓴 문장만 온다고 가정하면 안 된다.

### 방어 전략: sanitize 가 아니라 "HTML 을 애초에 파싱하지 않는 것"

결과를 **React 노드로 조립**하고 `dangerouslySetInnerHTML` 을 쓰지 않는다.
그래서 원문에 `<script>` 나 `<img onerror=...>` 가 들어 있어도 **그냥 글자로** 나간다.

이게 `react-markdown + rehype-sanitize` 를 안 쓴 이유이기도 하다:

> `allowedElements` 를 잘못 잡으면 오히려 위험해지는데, **파싱하지 않으면 그 실수 자체가
> 불가능하다.**

**링크·이미지는 어느 채널에서도 지원하지 않는다** — 문법을 열지 않으면
`[텍스트](javascript:...)` 경로가 애초에 생기지 않는다.

### 지원 블록 3종

`heading`(옵션) · `paragraph` · `list`(ordered/unordered).

`<ol start>` 에 **원문의 첫 번호를 그대로 넘긴다**:

> AI 가 매긴 번호와 화면의 번호가 어긋나면 사용자가 "2번"으로 답하는 경로(챗 되물음)가 깨진다.

### 스트리밍 대응 — `danglingEmphasis`

닫히지 않은 `**` 를 강조 **시작**으로 본다.

> 토큰이 한 글자씩 도착하는 동안 `**3건` 은 매 프레임 지나가는 중간 상태인데, 이때 별표를
> 글자로 내보내면 **화면에서 깜빡였다 사라진다.** 미리 굵게 잡아 두면 닫는 `**` 가 도착해도
> 굵기가 그대로라 글자가 튀지 않는다.

정적 문서에서는 끈다(짝이 안 맞는 `**` 는 평문으로 남는다).

### 챗에서는 `#` 제목을 끈다

기능이 아니라 **합의를 지키기 위한 장치**다:

> 말풍선에 제목 계층이 필요할 만큼 긴 답변은 내보내지 않기로 AI팀과 합의했다.
> 마커를 떼어 그럴듯하게 그려 주면 **합의 위반이 조용히 묻히므로**, 글자로 남겨
> 회귀가 눈에 띄게 한다.

## 4. 한국어 조사 자동 선택 (`josa.ts`)

**"은(는)" 같은 병기를 안 쓰려고** 만든 유틸. 상품명처럼 사용자 데이터를 문장에
끼워 넣을 때 필요하다.

```ts
withJosa("린넨 셔츠", "은")  // → "린넨 셔츠는"
withJosa("맨투맨", "은")     // → "맨투맨은"
```

### 한글 — 유니코드 산술로 받침을 판정

> 한글은 유니코드에서 (초성·중성·종성) 조합이 **순서대로** 배열돼 있어,
> 가(`0xAC00`)로부터의 거리를 **28(종성 개수)로 나눈 나머지**가 곧 종성 인덱스다. 0이면 받침 없음.

```ts
(code - 0xac00) % 28 !== 0
```

### 숫자·영문은 "읽는 소리"로 판정

상품명이 영문·숫자로 끝나는 경우가 흔하다(예: `"코튼 팬츠 2XL"`).

| 종류 | 받침 있는 것 | 근거 |
|---|---|---|
| 숫자 | `1 3 6 8 0` | 일·삼·육·팔·영 |
| 영문 | `L M N R` | 엘·엠·엔·아르 |

### 판별 불가면 병기로 물러난다

기호·한자로 끝나면 `null` → `"…은(는)"` 으로 병기한다.
**틀리게 붙이느니 병기가 낫다**는 판단.

`으로/로` 는 넣지 않았다 — ㄹ 받침이 예외("서울로")라 규칙이 하나 더 필요해서,
쓸 일이 생기면 그때 넣기로 했다.

## 5. 노출 측정 — MRC 기준을 그대로 쓴다 (`useVisibleOnce`)

상품 카드가 "봤다"고 인정되는 기준:

```
면적 50% 이상이 1초 이상 연속 노출   ← MRC 광고 노출 기준
```

**왜 임의로 정하지 않았나:**

> 임의로 정하면 나중에 근거를 댈 수 없고, **기준이 흔들리면 CTR 자체가 비교 불가능해진다** —
> 알고리즘을 안 바꿔도 FE 구현이 바뀌면 수치가 출렁인다.

바꾸려면 배포가 필요하므로 **변경 시점을 기록해 집계 구간을 나눠야 한다.**

### "1회만"이 핵심

> 스크롤로 같은 카드가 다시 보여도 재발화하지 않는다.
> 재발화하면 **노출 수가 뻥튀기돼 CTR 분모가 부풀려진다.**

발화 후 `observer.disconnect()` 로 관찰 자체를 끊는다.

### "연속" 1초라 중간에 가려지면 다시 센다

기준 미달로 내려가면 타이머를 접는다. `threshold: 0.5` 로 관찰하되,
콜백에서 `intersectionRatio` 를 다시 확인한다.

`key` 가 바뀌면 다른 대상으로 보고 재관찰한다(목록 교체).
`IntersectionObserver` 가 없으면(구형·테스트) **수집만 못 하고 화면은 정상 동작**한다.

콜백은 ref 로 들고 있는다 — 매 렌더 새로 만들어져도 옵저버를 다시 붙이지 않게.

## 6. 업로드 전 이미지 리사이즈 (`resizeImage.ts`)

canvas 로 축소하고 **WebP(미지원 시 JPEG)로 통일**한다. 세 문제를 한 번에 푼다:

| # | 문제 | 해결 |
|---|---|---|
| 1 | **HEIC** — iPhone 기본 포맷인데 Chrome 이 렌더링 못 함 | canvas 통과 자체가 "브라우저가 읽을 수 있다"는 검증 |
| 2 | **용량** — S-6 상한 2MB, 원본은 4MB 초과 | WebP 가 같은 화질에서 JPEG 보다 25~35% 작다 |
| 3 | **규격** — 기존 상품이 전부 긴 변 1000px | 거기 맞춘다(실측 2026-08-09) |

HEIC 를 그대로 올리면 **업로드는 성공하는데 화면에 안 보인다** — 더 나쁜 실패다.
1200px 로 올리지 않는 이유는 새 상품만 커져 목록 통일감이 깨져서다.

### ⚠️ 브라우저 함정 2개 (둘 다 조용히 실패한다)

**① `toBlob` 은 지원하지 않는 타입을 받아도 예외를 던지지 않는다**

> 명세상 조용히 PNG 로 폴백한다. 그러면 내용은 PNG 인데 `image/webp` 라고 선언한 파일이
> 올라가고, S-6 의 확장자·contentType 검사도 통과해버린다.

→ 요청한 타입이 아니라 **돌아온 `blob.type` 을 믿고** 다음 후보로 내려간다.

**② iOS Safari 는 canvas 메모리 한계를 넘어도 에러를 안 던진다**

> **빈 이미지를 반환한다** — 그대로 올리면 **흰 사각형이 상품 사진으로 등록되고
> 아무도 알아채지 못한다.**

→ `MIN_VALID_BYTES = 1024` 미만이면 실패로 보고, 긴 변을 `1000 → 800 → 500` 으로 낮춰 재시도.

### 폴백이 2단 — 포맷이 바깥, 크기가 안쪽

```
for (포맷 of [webp, jpeg])        ← 바깥
  for (긴 변 of [1000, 800, 500]) ← 안쪽
```

- 빈 이미지(`< 1KB`) → `continue` (크기를 줄여 재시도)
- 타입 불일치 → `break` (**이 포맷은 미지원이라 크기를 줄여도 소용없다**)

**크기가 안쪽인 이유:**

> WebP 를 지원하는 브라우저가 메모리 한계 때문에 JPEG 로 떨어지면 **용량 이득을 통째로 잃는다.**
> 포맷을 먼저 지키고 크기를 양보한다.

iOS Safari 의 canvas 메모리 한계는 기기마다 달라 1000px 이 실패해도 500px 은 통과하는
경우가 있다 — 화질이 조금 떨어져도 **아예 못 올리는 것보다 낫다**(카드는 300px 남짓으로 표시).

브라우저 지원 여부를 미리 묻지 않고 **실제 결과의 타입으로 판정**한다.

### 투명 PNG는 흰 배경으로 채운다

투명한 채로 두면 배경이 비쳐 목록에서 튄다. WebP 는 투명도를 지원하지만
상품 사진은 흰 배경으로 통일한다(JPEG 시절과 같은 결과 유지).

### ⚠️ EXIF 회전은 다루지 않는다

`createImageBitmap` 을 **옵션 없이** 호출한다(`imageOrientation` 미지정).
현행 스펙 기본값은 `"from-image"` 지만 구현 편차가 있는 영역이라,
세로로 찍은 사진이 눕는 회귀가 이론적으로 가능하다. **브라우저 기본 동작에 위임한 상태 —
개선 여지.**

### 파일명 확장자도 실제 출력에 맞춘다

S-6 는 확장자와 contentType 이 어긋나면 `IMAGE_TYPE_UNSUPPORTED` 로 막는다 —
`photo.heic` 를 그대로 보내면 `heic + image/webp` 조합이 되어 거부된다.

### 리사이즈 실패 시 원본으로 폴백하지 않는다

> 원본은 2MB 상한에 걸리기 쉽고, HEIC 면 올라가도 화면에 안 보인다
> (**성공한 것처럼 보이면서 상품 사진이 깨지는 쪽이 더 나쁘다**).

### 업로드는 presigned URL 2개를 구분해 쓴다

| URL | 용도 | 특징 |
|---|---|---|
| `uploadUrl` | S3 PUT 전용 | 서명·만료 포함, 1,000자 초과, **5분 뒤 죽는다.** 쓰고 버린다 |
| `imageUrl` | 상품에 저장 | 쿼리스트링 없는 canonical URL |

`image_url` 컬럼이 `VARCHAR(500)` 이라 presigned 쪽은 **애초에 들어가지도 않는다.**
서버가 두 값을 이름 붙여 내려주므로 **FE 가 파싱해 만들지 않는다** —
CDN 이 앞에 붙거나 서명 방식이 바뀌면 파싱 규칙이 조용히 깨진다.

S3 PUT 에는 `api` 인스턴스를 쓰지 않는다 — baseURL·인증 쿠키·에러 인터셉터가 전부
우리 서버용이라 **서명이 어긋나거나 불필요한 자격증명이 실린다.**

발급 요청에 `size` 를 싣는 이유: presigned PUT 은 "이하"를 걸 수 없고 서명에 들어간
`Content-Length` 가 **일치 조건**이라, 서버가 상한을 검사한 뒤 그 값을 서명에 박는다.

## 7. 상품 이미지 (`ProductImage.tsx`)

**`next/image` 를 쓰지 않는다.** `next.config.ts` 에 `images.remotePatterns` 가 없어서
S3 호스트가 등록돼 있지 않다 — 도입하려면 그 등록이 선행돼야 한다.

### 실패는 상시 일어난다고 보고 만들었다

> 이미지가 지워졌거나, 스토리지 URL 이 잘못 내려오거나(**실제로 버킷명이 어긋나
> 전 상품이 깨진 적 있음**), 오프라인이거나.

대체 화면이 없으면 브라우저 기본 깨진 아이콘이 뜨는데, **카드 레이아웃이 그대로 무너져 보인다.**
카드마다 따로 처리하면 화면별로 실패 모습이 갈리므로 **여기 하나로 모은다.**

### ⚠️ `src` 가 없을 때 빈 문자열을 넣으면 안 된다

> 브라우저가 **현재 페이지를 다시 요청해** 불필요한 트래픽이 생긴다.

그래서 `!src` 를 실패와 **같이** 취급해 대체 화면으로 보낸다.

### `alt` 유무로 접근성 처리가 갈린다

```tsx
alt ? { role: "img", "aria-label": `${alt} (이미지 없음)` }
    : { "aria-hidden": true }
```

`alt=""` 는 **장식용**(옆에 상품명이 이미 있음)이라는 뜻이므로 대체 화면도 숨긴다 —
이름을 두 번 읽히지 않게.

### `fetchPriority` 는 화면당 한 장만

> `loading="eager"` 는 "지연하지 말라"일 뿐 **순서를 정하지 않아** 같이 대기 중인
> 다른 리소스와 경쟁한다. 이 값이 그 경쟁에서 먼저 가져올 것을 지정한다.
> 남용하면 서로 밀어내 의미가 없어진다.
