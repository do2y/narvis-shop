### 이번 검증에서 잡은 버그 5건
브라우저에서만 드러난 것들이다 — 자동 검증(curl·빌드)은 전부 통과했었다.

1. **프록시 gzip** (`ERR_CONTENT_DECODING_FAILED`) — fetch가 압축을 풀었는데
   `Content-Encoding` 헤더를 그대로 전달. curl은 `Accept-Encoding`을 안 보내 재현 안 됨
2. **카드 시딩 훅 콘솔 에러** — `useQuery`가 `enabled:false`여도 `queryFn` 부재를 에러로 봄.
   원본에도 있던 문제(원본은 `fix/seeded-card-queryfn` 브랜치에서 별도 수정)
3. **결제 후 `/checkout` 직접 진입 시 이전 주문 표시** — `location.state`(히스토리 엔트리별)를
   sessionStorage(탭 전체)로 바꾸며 생긴 차이. 결제 성사 시 항목을 비우도록 수정
4. **필터·정렬이 화면에 반영되지 않음** — 두 겹의 문제였다
   - SSR 결과(`initialData`)를 모든 쿼리 키에 주입 → 정렬 변경 시 새 키에도 옛 데이터가
     초기값으로 들어가고 `staleTime`(30분) 때문에 재조회조차 안 함
   - 화면 내 쿼리 갱신에 `router.push` 사용 → 주소창 미반영.
     Next 문서가 이 사례(목록 정렬)에 `window.history.pushState`를 안내한다.
     `useQueryParams`도 같이 고쳐 셀러 목록 필터에도 적용됨
5. **홈에서 넘긴 첫 질문(`?q=`)이 전송되지 않음** — q를 `useClientValue`
   (`useSyncExternalStore`)로 읽었더니 첫 패스 `null` → 실제값 전환 타이밍이 어긋나
   이펙트가 전송을 놓쳤다. 마운트 1회 이펙트 + `useRef` 가드로 되돌림.
   URL 정리도 `router.replace` → `history.replaceState`(라우트 이동이라 스트리밍이 끊김)

### 배운 것 — 도구 선택 기준
`useClientValue`는 **렌더에 쓸 값**용이다(결제 화면의 sessionStorage state).
**이펙트에서 1회 실행**하는 용도에는 맞지 않는다 — 그때는 `useRef` 가드 + 이펙트 안에서
`window.location` 직접 읽기가 맞다. 5번은 이 구분을 놓쳐서 생긴 버그다.

## 시작하기

```bash
cd jarvis-web-next
npm run dev          # → http://localhost:3000
```

포트 3000 고정 — 백엔드 CORS가 이 주소만 허용한다. 원본 dev 서버가 떠 있으면 먼저 끈다.
원본으로 되돌리려면 이 서버를 끄고 레포 루트에서 `npm run dev`.

**브라우저 준비**
- **F12로 개발자도구를 열고 시작한다.** Console 탭 + Network 탭 둘 다 본다
- 첫 진입 시 **Ctrl+Shift+R**(하드 리프레시) — 이전 버전이 캐시돼 있을 수 있다
- 시크릿 창을 쓰면 게스트 상태에서 깨끗하게 시작할 수 있다

**기록 방법**: 각 시나리오 끝의 `기대` 와 다르면 그 지점에서 멈추고 **화면 + 콘솔 메시지 + 네트워크 탭의 빨간 줄**을 알려주면 된다. 지금은 원본 앱이 배포 중이라 급할 것 없다.

### ⚠️ 검증 전 확인할 것 두 가지

**① 지금 보는 게 Next 앱이 맞는가**
원본(Vite)과 Next가 같은 3000 포트를 쓰므로 헷갈리기 쉽다. 실제로 원본을 Next로 착각해
"수정이 반영 안 된다"고 판단한 적이 있다.
- 탭 제목: 원본 `jarvis-web` / Next `Jarvis — 대화로 찾는 쇼핑`
- 또는 개발자도구 우하단의 Next 개발 인디케이터(N 아이콘) 유무

**② 동적 라우트만 404가 나면 dev 캐시 문제**
`/products/[id]`·`/brands/[id]`는 404인데 `/`·`/cart`는 정상이라면 코드가 아니라
`.next/dev` 캐시가 깨진 것이다(dev·prod 서버를 번갈아 띄우면 생길 수 있음).
```bash
rm -rf .next/dev && npm run dev   # 빌드 결과물은 유지되고 dev 캐시만 지운다
```

# 🔴 시나리오 1 — 게스트 구매 흐름 (최우선)

가장 위험하다. 원본 `location.state`를 sessionStorage로 **바꾼 곳**이라 동작이 달라질 수 있다.

1. **시크릿 창**으로 `http://localhost:3000` 진입
   - 기대: 인기 상품이 보인다. 콘솔에 빨간 에러 없음
2. 상품 카드 아무거나 클릭
   - 기대: 상세로 이동. **깜빡임 없이** 상품명·가격이 바로 보인다(SSR)
3. 옵션이 있으면 옵션 선택, 수량을 2로 변경
   - 기대: 가격이 옵션 추가금만큼 반영된다
4. **장바구니** 버튼 클릭
   - 기대: "장바구니에 담았어요" 표시, **헤더 장바구니 뱃지가 1로** 변한다
5. 헤더 장바구니 아이콘 클릭 → `/cart`
   - 기대: 방금 담은 상품이 옵션·수량 그대로 보인다
6. 수량을 3으로 변경
   - 기대: 합계 금액이 바뀌고 **헤더 뱃지도 따라 변한다**
7. 상품 선택 후 **주문하기**
   - 기대: 로그인 화면으로 이동 (게스트는 구매 불가). 주소창에 **`?returnUrl=`이 붙어 있다**

> **여기서 멈추면 안 되는 것**: `/checkout`이 빈 화면으로 뜨거나 "주문 정보를 찾을 수 없어요"가 뜨면 sessionStorage 전달이 깨진 것 → 보고

# 🔴 시나리오 2 — 로그인과 세션 유지

AT를 메모리에만 두는 구조라, 새로고침 복원이 이번 이식의 핵심 위험 중 하나다.

1. 시나리오 1에서 이어서 (또는 `/login` 직접 진입) 로그인
   - 기대: 로그인 성공 → **아까 가려던 장바구니/결제 화면으로 복귀**(returnUrl 동작)
2. **F5로 새로고침**
   - 기대: **로그인 상태가 유지된다.** 헤더에 닉네임이 그대로 보인다
   - 실패 예: 로그인 화면으로 튕김 / 헤더가 "로그인·시작하기"로 되돌아감
3. Network 탭 확인
   - 기대: `/api/auth/refresh` → 200, `/api/auth/me` → 200
   - 실패 예: 401이 반복해서 찍힘
4. 마이페이지 진입 → 새로고침
   - 기대: 마이페이지가 그대로 유지된다 (가드가 로그인으로 튕기지 않음)
5. 로그아웃 → 새로고침
   - 기대: 게스트 상태 유지, 콘솔에 401 반복 없음

# 🔴 시나리오 3 — 회원 구매 완주 (결제까지)

시나리오 1에서 막혔던 결제를 끝까지 간다. **가장 많이 바뀐 경로다.**

1. 로그인 상태로 상품 상세 진입
2. **바로 구매** 클릭
   - 기대: `/checkout`으로 이동하고 **상품·옵션·수량·금액이 표시된다**
   - 실패 예: 빈 화면 / **"주문할 상품이 없어요"가 뜬다** → sessionStorage 전달 실패
3. 배송지 선택 (없으면 추가)
   - 기대: 주소 검색·저장이 동작한다
4. 결제 수단 선택 → **결제하기**
   - 기대: `/checkout/complete`로 이동, **주문번호·상품·결제금액**이 보인다
5. **뒤로가기(←)** 누르기
   - 기대: 결제 화면으로 **돌아가지 않는다**(replace 이동). 중복 결제 방지
6. 마이페이지 → 주문 내역
   - 기대: 방금 주문이 목록에 있다. 상세도 열린다
7. `/checkout`을 **주소창에 직접 입력**해 진입
   - 배경: 결제 화면은 자체 데이터가 없다. "바로 구매"·"주문하기"에서 주문 항목을
     들고 들어오는 구조라, 직접 진입하면 들고 올 게 없다
   - 기대: **"주문할 상품이 없어요"** + "상품 상세 페이지에서 '바로 구매'를 눌러
     주문을 시작해주세요." + **[홈으로]** 버튼 (원본 checkout/index.tsx의 빈 상태 화면)
   - 실패 예: 빈 화면(헤더만) / 에러·크래시 / 결제 폼이 상품 없이 그대로 뜸
   - 같은 방식으로 `/checkout/complete` 직접 진입 → "주문 정보를 찾을 수 없어요"

**장바구니 경유도 한 번 더**: `/cart`에서 선택 → 주문하기 → 결제 완주. 담긴 상품이 결제 화면에 넘어오는지 확인.

# 🟡 시나리오 4 — 챗봇

`?q=` 처리 방식을 바꿨고, 스트리밍은 curl로 확인이 어렵다.

1. 홈 히어로 입력창에 "겨울 패딩 추천해줘" 입력 후 전송
   - 기대: `/chat`으로 이동하며 **그 질문이 자동 전송**된다
2. 답변 관찰
   - 기대: **한 글자씩 그려진다**
   - 실패 예: 한참 멈췄다가 전체가 한 번에 나타남 → 스트리밍 깨짐
3. 주소창 확인
   - 기대: **`?q=`가 사라져 있다**(새로고침 시 재전송 방지)
4. 새로고침
   - 기대: 대화가 초기화된다(persist 안 함 — 의도된 동작). 질문이 재전송되지 않는다
5. 조건 칩이 나오면 **X로 하나 제거**
   - 기대: "[조건 제거] ..." 메시지가 나가고 결과가 갱신된다
6. 추천 카드 클릭
   - 기대: 상품 상세로 이동, **즉시 렌더**(캐시 시딩 — 스켈레톤이 길게 보이면 안 됨)
7. 챗봇에서 장바구니 담기(가능하면)
   - 기대: **헤더 뱃지가 즉시 오른다**
8. 홈 카테고리 그리드에서 카테고리 클릭
   - 기대: 해당 카테고리 질문으로 챗봇 진입

# 🟡 시나리오 5 — 브랜드 필터 (URL 쿼리로 바뀐 곳)

원본은 `useState`였다. 이번에 URL로 올려 색인 가능하게 만들었다.

1. 상품 상세 → **브랜드명** 클릭 → 브랜드 홈
2. 정렬을 **낮은 가격순**으로 변경
   - 기대: 주소창에 **`?sort=price_asc`**가 붙고 목록 순서가 바뀐다
3. 카테고리 칩 선택
   - 기대: `?category=` 반영, 목록이 줄어든다
4. **뒤로가기**
   - 기대: 이전 필터 상태로 돌아간다
5. 현재 URL을 복사해 **새 탭에 붙여넣기**
   - 기대: 같은 필터가 적용된 화면이 뜬다
6. 필터를 다시 바꿔본다
   - 기대: **스크롤이 맨 위로 튀지 않는다**
7. 페이지가 2개 이상이면 다음 페이지 이동
   - 기대: `?page=` 반영, 목록 갱신

# 🟡 시나리오 6 — 마이페이지 전체

splat 라우트를 폴더 구조로 펼친 곳이다. 좌측 메뉴 활성 표시가 특히 의심스럽다.

1. 마이페이지 진입 → 좌측 메뉴를 **하나씩 전부** 클릭
   - 주문 내역 / 취소·반품 / 최근 본 상품 / 찜 / 배송지 관리 / 문의 내역
   - 기대: 각 화면이 뜨고 **현재 메뉴가 활성 표시**된다(NavLink 치환 지점)
2. 주문 내역 → 주문 하나 클릭 → 상세
   - 기대: 상세가 열리고, **좌측 메뉴는 "주문 내역"이 활성 유지**
3. 배송완료 주문이 있으면 **리뷰 작성**
   - 기대: 별점·내용 입력 후 등록, 완료 화면
4. `/mypage/reviews/new`를 **파라미터 없이** 주소창에 입력
   - 기대: 주문 내역으로 되돌려보낸다
5. 배송지 **추가 → 수정 → 삭제**
6. 헤더 찜 아이콘(`/wishlist`) 클릭
   - 기대: 회원이면 `/mypage/wishlist`로 이동

# 🟢 시나리오 7 — 판매자 (계정 있는 경우만)

1. 판매자 계정으로 로그인

   - 기대: `/seller`로 되돌려보낸다(판매자 격리)

   - 특히: `/seller/orders`에 있을 때 **"대시보드"가 활성이면 안 된다**(정확 일치 판정)

   - 기대: 주소창에 쿼리가 반영된다
5. AI 어시스턴트 화면
   - 기대: **헤더 메뉴가 숨겨진다**(원본 동작), 스트리밍 응답이 한 글자씩

# 🟢 시나리오 9 — 모바일 (프로젝트 필수 규칙)

개발자도구에서 폭을 **360px**로 줄이고 주요 화면 확인.

- [ ] 홈 · 상품 상세 · 장바구니 · 결제 · 마이페이지
- [ ] **가로 스크롤이 생기지 않는다**
- [ ] 마이페이지 좌측 메뉴가 **가로 스크롤 필**로 바뀐다
- [ ] 판매자 헤더 메뉴가 아래 줄로 분리된다
- [ ] 버튼이 손가락으로 누를 만한 크기(≥44px)

# ⚠️ 전 과정에서 계속 볼 것

**Console 탭**
- [ ] 빨간 에러 없음
- [ ] **하이드레이션 불일치 경고** 없음 — `Hydration failed`, `Text content did not match`
      *(sessionStorage·window를 읽는 결제·챗봇 화면에서 나기 쉽다)*
- [ ] 무한 렌더 경고 없음

**Network 탭** ← *이번 gzip 버그가 여기서만 보였다*
- [ ] **빨간 줄이 없다** (`ERR_CONTENT_DECODING_FAILED`, `net::ERR_*`)
- [ ] `/api/*` 요청이 200/401 등 의미 있는 상태로 온다 (500 연발 아님)
- [ ] 같은 요청이 **비정상적으로 반복**되지 않는다
