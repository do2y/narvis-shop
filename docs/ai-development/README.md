# AI 활용 개발 기록

Claude Code·ChatGPT 같은 생성형 AI로 개발하면서 **무엇을 맡겼고, 어디서 틀렸고, 사람이 어떻게 검증했는지**를 남기는 곳.

## 원칙 — 기술 내용은 복제하지 않는다

- **기술 설명의 정본은 기존 문서임.** 구조는 `architecture/`, 사고는 `troubleshooting/`, 수치는 `performance/`.
  이 폴더에는 **과정만** 적고, 기술 내용은 링크로 연결함
- 같은 내용을 두 군데 쓰면 한쪽만 고쳐져 어긋남(→ [claude-md-drift.md](claude-md-drift.md)가 그 실제 사례)
- AI가 낸 결과를 그대로 성과로 쓰지 않음. **사람이 무엇을 확인했고 무엇을 고쳤는지**가 이 기록의 핵심임
- 확인하지 않은 효과(시간 절감 등)는 수치로 쓰지 않음

## 파일 규칙

- 파일명 `YYYY-MM-DD-<주제>.md` (예: `2026-11-03-sse-parser-test.md`)
- 한 기록 = 한 작업. 여러 세션에 걸쳐도 같은 작업이면 한 파일에 이어 씀
- 관련 기술 문서 끝에 역링크 한 줄을 다는 것은 선택 (`> AI 개발 기록: [...](../ai-development/...)`)

## 템플릿

```md
# <작업 제목>

> 날짜 · 도구(Claude Code / ChatGPT) · 관련 커밋/PR

## 맡긴 것
- 어떤 문제였고 AI에게 무엇을 요청했나 (프롬프트 요지 — 전문은 필요할 때만)

## AI가 낸 것
- 산출물 요약. 기술 내용은 쓰지 않고 해당 문서로 링크

## 사람이 잡은 것
- AI가 틀렸거나 놓친 지점, 발견한 방법 (테스트·빌드·실측·코드 대조)

## 결과
- 최종 반영 내용과 검증 방법

## 관련 문서
- [기술 문서](../architecture/....md) §n
```
