## 작업 목적

T2 의 E2E 15건은 **로컬에서만** 돌았다. CI(`ci.yml` 의 `check` 잡)는 ESLint · Vitest · build 만 실행해서,
T2 가 지키는 회귀 계약(재전송 없음 · 중단 상태 구분 등)이 PR 에서 자동으로 확인되지 않았다
([T2 최종 검토 §9](2026-11-09-browser-e2e/t2-final-review.md#9-테스트-인프라와-환경적-한계)의 "CI 미연결").

이번 작업은 **테스트를 늘리거나 바꾸지 않고**, 기존 15건을 CI 에서 같은 조건으로 실행하는 것이 범위다.

| 테스트 서버 | 테스트 백엔드 `127.0.0.1:4010` 고정, SSE 서버 `127.0.0.1` 임의 포트 · 테스트마다 fixture 가 띄우고 닫음 | 새 러너에서는 포트 충돌 요인이 없다 |
| 실행 방식 | `workers: 1` · `retries: 0` · CI 에서 `forbidOnly` · `trace: retain-on-failure` · html 리포트 | 재시도로 불안정성을 숨기지 않는다 — 그대로 유지 |
| 동기화 | 고정 sleep 없음 · `route()` 가로채기 없음 · D1a 의 서버 수신 횟수는 관찰값(단언 아님) | 러너 OS 차이로 관찰값이 달라져도 단언이 깨지지 않는다 |
| Node | 기존 CI · Dockerfile 모두 20 · Next 요구 ≥20.9 · **T2 로컬 검증은 Node 24** | CI 와 맞춰 20 을 쓰고, 로컬도 20 으로 다시 확인 |

## 워크플로 구조

`ci.yml` 에 **독립 잡 `e2e`** 를 추가했다. 기존 `check` 잡과 실행 조건(`pull_request` · `main` push · 수동 실행)은 그대로다.

```
pull_request / push(main) / workflow_dispatch
 ├─ check  (기존) npm ci → eslint → vitest → build
 └─ e2e    (신규) npm ci → playwright install --with-deps chromium → npm run test:e2e
                  └ 실패 시: playwright-report/ · test-results/ 아티팩트 업로드(7일)
```

| 결정 | 근거 |
|---|---|
| `check` 에 단계를 붙이지 않고 별도 잡 | 병렬 실행 · E2E 실패가 린트/단위 테스트 실패와 섞이지 않는다 |
| 빌드가 두 번 돈다(`check` · `webServer`) | 빌드 산출물을 공유하려면 T2 설정(`webServer.command`)을 바꿔야 한다. 이번 범위에서는 설정 불변을 우선하고 시간 비용을 택했다 |
| `permissions: contents: read` (e2e 잡만) | 체크아웃 외 권한이 필요 없다. 기존 `check` 잡의 권한은 범위 밖이라 건드리지 않음 |
| `timeout-minutes: 20` | 로컬 기준 빌드+테스트 약 1~2분. 러너가 느려도 넉넉하고, 매달림은 20분에 끊긴다 |
| Chromium 만 설치 · 브라우저 캐시 없음 | 설정의 프로젝트가 chromium 하나 · 단순하게 시작하고 시간이 문제면 그때 추가 |
| 아티팩트는 실패 시에만 | 실패 분석용(trace · 스크린샷 · 리포트). 통과 시 남길 필요 없음 |

실행 중 프로세스의 바이너리를 확인해 **Playwright 러너와 `next-server` 모두 임시 Node 20 바이너리**였음을 확인했다.

|---|---|---|
| Playwright E2E (`CI=true npm run test:e2e`) | Node **v20.20.2** · npm 11.19.0 · macOS · Chromium 헤드리스 | **15/15 통과** (34.2s) |
| Vitest | Node 20.20.2 | 40 파일 **526건** 통과 |
| ESLint · TypeScript(`tsc --noEmit`) | Node 20.20.2 | 통과 |
| 워크플로 YAML | Ruby YAML 파서 | 파싱 성공 · 잡 `check`/`e2e` · 트리거 3종 기존과 동일 · e2e 권한 `contents: read` |
| D1a 관찰값 | Node 20 | keep-alive 조건 서버 수신 2 · 나머지 두 조건 1 — T2(Node 24) 기록과 같음 |

`next start` 의 standalone 경고(T2 와 같은 알려진 한계)가 출력됐고, `ECONNREFUSED`(4010) 로그는 이번 실행에서 0건이었다.

PR [#12](https://github.com/do2y/narvis-shop/pull/12) 의 `pull_request` 실행 · `ubuntu-latest` · 2회. 두 번째 실행은 문서 커밋 push 로 시작됐다(워크플로·테스트·제품 코드는 첫 실행과 같다).

| 실행 | 커밋 | `check` (기존) | `e2e` (신규) |
|---|---|---|---|
| 1 · [42759039854](https://github.com/do2y/narvis-shop/actions/runs/42759039854) | `76d7735` | **success** · 81s | **success** · 190s |
| 2 · [42759754794](https://github.com/do2y/narvis-shop/actions/runs/42759754794) | `aaf1d60` | **success** · 80s | **success** · 191s |

단계별 소요(1차 / 2차):
- `check` — npm ci 16s / 14s · eslint 12s / 12s · vitest 22s / 25s · build 17s / 19s
- `e2e` — npm ci 14s / 15s · **playwright install --with-deps 123s / 114s** · test:e2e(앱 빌드 포함) 38s / 47s · 아티팩트 업로드 두 번 모두 skipped(실패 없음)

**확인한 사실** (공개 저장소라 잡·단계 결과와 주석(annotation)을 인증 없이 API 로 읽었다):
- 두 실행 모두 두 잡과 위의 각 단계가 success 로 끝났고, 실패 시 업로드 단계는 실행되지 않았다(아티팩트 0개)
- 위에서 미확인으로 남겼던 Linux 러너 · `--with-deps` 설치 · 새 `npm ci` · 러너 성능 · 이름 해석은 **이 2회 실행에서 테스트 단계를 실패시키지 않았다**

**확인하지 못한 것**: 잡 로그 본문은 인증이 필요해(403) 보지 못했다. **15건 각각의 통과 로그와 "15 passed" 요약을 직접 확인하지 않았고**, 러너에서 실제로 쓰인 Node 버전 문자열도 보지 못했다(설정은 `node-version: 20`).

**추론** (직접 확인 아님): 15건이 모두 실행·통과했다고 본다. 근거는 `playwright test` 가 실패가 하나라도 있으면 0 이 아닌 코드로 끝나 단계가 실패한다는 점 · `e2e/` 에 `skip` · `fixme` · `only` · `test.fail` 이 없다는 점 · CI 에서 `forbidOnly` 가 켜진다는 점이다. test:e2e 가 38s → 47s 로 늘어난 원인(앱 빌드 · 테스트 중 어느 쪽인지)은 로그 없이 모른다

실행에서 나온 주석(두 실행 · 두 잡 공통, 같은 2건, 테스트 결과와 무관):
- **warning** — `actions/checkout@v4` · `actions/setup-node@v4` 가 내부적으로 Node 20 을 대상으로 해 러너가 Node 24 로 강제 실행했다. 액션 자체의 런타임 문제이며, 앱을 돌리는 `node-version: 20` 과는 별개다. 기존 `check` 잡에도 같은 경고가 있다
- **notice** — `ubuntu-latest` 가 2026-10-19 부터 Ubuntu 26 으로 이전 중. 이번 실행이 어느 버전에서 돌았는지는 로그를 못 봐서 모른다

## 검증하지 못한 것

- **장기 안정성** — CI 실행은 2회다. 간헐 실패가 없다고 말하기에는 표본이 작고, 러너 성능 차이로 인한 실패 여부는 실행이 쌓여야 안다
- **로그 본문** — 테스트별 소요 시간 · D1a 관찰값 · `ECONNREFUSED` 로그 여부 · 러너 OS 버전은 CI 에서 확인하지 못했다
- T2 가 이미 남긴 한계(standalone 미사용 · nginx 미경유 · Chromium 만)는 CI 에서도 그대로다
- 앱의 Node 20 자체 — CI · Dockerfile 모두 20 이지만 Node 20 은 2026-04 에 지원이 끝났다. 버전 변경은 운영 이미지와 함께 정할 일이라 이번 범위에서 다루지 않았다

## 발생한 문제와 처리

로컬 검증과 CI 2회 실행 모두에서 실패나 테스트 수정은 없었다. 문제로 남긴 것은 위의 작업 기점 정정과 액션 런타임 경고뿐이다.
**이후 CI 에서 실패하면** 재시도·단언 완화로 넘기지 않고, 아티팩트의 trace 로 **테스트 환경 문제(러너 성능 · 설치 · 이름 해석)와 제품 결함을 구분**해 이 문서에 남긴다.

후보(이번 범위 밖, 결정 필요):
- e2e 잡 시간의 2/3 가 브라우저 설치(123s)다. 캐시를 두면 줄일 수 있지만 `--with-deps` 의 시스템 패키지는 캐시되지 않아 효과가 제한적일 수 있다
- 액션 런타임 경고 — `actions/checkout` · `actions/setup-node` 상위 버전으로 올리는 일은 기존 `check` 잡과 `deploy.yml` 에도 걸려 있어 별도로 다룬다
