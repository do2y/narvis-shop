# T2-B1 · 이전 턴의 카드 조회가 새 대화에 유입되는가

> 2026-11-09 · 테스트 [e2e/b1-stale-card-fetch.spec.ts](../../../e2e/b1-stale-card-fetch.spec.ts) · 제품 코드 변경 없음

## 결론

- **기존 코드에서 결함이 재현되지 않았다.** 이전 턴의 CH-5 응답이 새 턴 시작 뒤 실제로 브라우저에 도착해도
  새 대화의 화면·응답 중 상태·저장소·새로고침 복원 어디에도 섞이지 않았다
- **T1 수정(`bd07411`, 턴 소유권)에 대한 실제 브라우저 회귀 테스트로 분류한다**(개발자 결정). 억지로 RED를 만들지 않았다
- 테스트가 그 결함을 실제로 잡는지는 격리 worktree의 결함 주입 M1·M2로 확인했다 — 둘 다 단언 실패.
  **M1·M2는 인위적으로 주입한 과거 결함이며 현재 제품의 결함이 아니다**

## 목적과 T1에서 이미 검증한 범위

T1은 [03 §10](../2026-10-31-chat-turn-test/03-validation.md)에서 턴 소유권을 도입하며 다음을 jsdom으로 고정했다.

| T1 | 내용 | 방식 |
|---|---|---|
| A1 | 카드 조회 중 새 대화 → 새 대화 `results`에 이전 카드가 들어오던 결함 | 훅·이벤트 핸들러 테스트, `fetchChatListGroup` 목 |
| A2·A3 | 세션 확보 중·답변 수신 중 새 대화 → 새 턴이 진행 중인데 `isStreaming` false | 훅 테스트, 세션 코디네이터 목 |

B1이 새로 보는 것 — jsdom에서는 볼 수 없던 것:

- **실제 HTTP 요청**이 서버에 도착한 채 붙잡혀 있다가 새 턴 시작 **뒤에** 200으로 도착하는 경쟁
  (CH-5 조회에는 abort 신호가 없어 새 대화로도 취소되지 않는다)
- 실제 React 렌더(카드 패널·말풍선·전송 버튼)
- `useChatPersistence`의 sessionStorage 저장과 **새로고침 복원**. T1 기록에 "수정 전엔 이전 카드가 저장까지 돼
  새로고침 후에도 남았다"는 서술이 있으나, 그 경로는 T1에서 테스트로 고정되지 않았다

## 재현한 경쟁 상황

1. `/chat`에서 이전 질문 전송 → 답변 → `products.ready{listIds:[old]}` → `done`
2. 이전 턴의 CH-5 요청이 **테스트 백엔드에 도착 — 서버가 응답을 붙잡는다.** 이전 턴은 카드 조회를 기다리며
   아직 응답 중이다(전송 버튼 잠김을 단언 — 경쟁의 전제)
3. 사용자가 **"새 대화"** 클릭 → 이전 질문이 화면에서 사라짐 → 새 질문 전송 → 새 턴 SSE가 서버에 도착, 진행 문구·답변 일부 표시
4. 테스트가 이전 CH-5를 **풀어준다** → 브라우저가 200을 본문까지 받음(`response.finished()` = 실패 없음)
5. 새 턴의 다음 프레임이 화면에 반영될 때까지 대기(동기화 지점) → 검증
6. 새 턴 완료(새 카드) → 저장소 확인 → 새로고침 → 복원 확인

### 순서 증명

고정 대기 없이 순서를 만든다 — 서버가 응답을 붙잡고, 테스트는 새 SSE 도착을 확인한 뒤에만 풀어준다.
서버·브라우저 사건 기록을 단언했다.

```
old-ch5:arrived-at-server → user:new-chat → new-sse:arrived-at-server
  → old-ch5:server-responded → old-ch5:delivered-to-browser
```

## 테스트 신뢰성 — 결함 주입 (격리 worktree)

스크래치패드의 `git worktree`(기점 `069db4c`)에서만 제품 코드를 바꿨다. 작업 트리의 `src/`는 건드리지 않았고,
각 실행 뒤 `git checkout`으로 원복하고 worktree는 제거했다.

| 실행 | 결과 | 집계 |
|---|---|---|
| 1차 기준 · M1 · M2 (`node_modules` 심볼릭 링크) | Turbopack이 빌드 단계에서 거부(`Symlink … points out of the filesystem root`) | **무효 — 환경 오류. 탐지로 세지 않음** |
| 2차 기준 (`node_modules`를 APFS 복제 `cp -c`로 교체) | 통과 | 환경 정상 확인 |
| **M1** CH-5 결과 반영의 `isCurrent()` 검사 제거 = T1 A1 결함 | ✘ 단언 (1) 실패 — 이전 턴 카드 링크 기대 0, 실제 1 | 검출 |
| **M2** `endTurn`의 소유권 검사 제거 = T1 A2·A3 증상의 원인 구조 | ✘ 동기화 지점 단언 실패 — 새 턴의 다음 답변 조각 미표시 | 검출 |

M2 해석: 이전 턴의 `finally`가 새 턴의 소유권까지 지워, 새 턴이 이후 프레임을 버리고 **답변이 멈췄다**.
단언 (2)(전송 잠김)에 닿기 전에 사용자에게 보이는 결과에서 먼저 실패했다. 이 결과는 동시에
"동기화 지점 시점에 이전 턴의 정리가 이미 실행됐다"는 전제의 근거이기도 하다 — 정상 실행에서는 직접 관찰하지 않는다.

> 1회 주입 결과다. 반복 실행·다른 변이 세트는 돌리지 않았다.

## 검증 한계

- **브라우저·실행**: Chromium 헤드리스 · `next start`만. Firefox·WebKit·standalone·dev(StrictMode) 미검증
- **화면 크기**: 데스크톱 기본값만. 모바일 레이아웃(카드 패널 위치·바텀시트) 미검증
- **동기화 전제**: "이전 응답 도착 뒤 새 턴의 다음 프레임 반영"을 기다린 뒤 판정한다 — 브라우저가 두 연결의 작업을
  도착 순서대로 처리한다는 전제다. 이를 보완해 새 턴 완료 뒤·새로고침 뒤에 한 번 더 확인한다
- **시나리오 범위**:
  - 이전 CH-5가 **실패**(404·5xx)하는 경우는 다루지 않았다 — 그 경로는 카드 대신 말풍선에 안내 문구를 붙인다
  - 세션 확보 중·SSE 수신 중 새 대화(T1 A2·A3의 원래 경로)는 브라우저에서 따로 재현하지 않았다
  - 같은 대화 안의 연속 질문(새 대화 없이)과 멀티탭은 범위 밖
- 목 서버는 계약 필드만 쓴다. 실제 BE의 CH-5 응답 지연 분포·캐시 동작은 모델링하지 않는다
