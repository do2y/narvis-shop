### M15 생존 → 원인 → 보완

1. **생존**: 1차에서 U1 테스트가 M15(즉시 abort) 아래에서도 통과함
2. **가설**: 이 환경에서 StrictMode 가짜 언마운트가 일어나지 않음
3. **확인** (worktree에서 진단 테스트 실행, 확인 후 삭제)

   | StrictMode를 거는 방식 | 이펙트 로그 |
   |---|---|
   | `renderHook(..., { wrapper })` 안에서 `<StrictMode>`로 감쌈 (1차 방식) | `mount` — **이중 실행 없음** |
   | `renderHook(..., { reactStrictMode: true })` (RTL이 루트에 StrictMode를 둠) | `mount → cleanup → mount` |

   환경: React 19.2.4 · react-dom 19.2.4 · `@testing-library/react` 16.3.3 · NODE_ENV=test.
   wrapper 방식에서 이중 실행이 일어나지 않는 React 내부 조건은 **확인 필요**(관찰만 함). 실제 앱은 Next가 루트에 거는 구조라 옵션 방식이 운영과 같은 모양임.
4. **보완**: `reactStrictMode: true`로 바꾸고, **전제 단언**(`lifecycle`이 `mount → cleanup → mount`인지)을 추가 — 재현 조건이 성립하지 않으면 테스트가 실패하도록 함
5. **재검증**: 원본에서 통과 → 2차에서 M15를 **본 단언**으로 검출(전제 단언이 아님)

**G9 — "동등" 판정이 틀렸음** 📌

| | 내용 |
|---|---|
| 원본 | `const fresh = await refreshTicket(…); if (!isCurrent()) return; setSessionId(fresh.sessionId); await streamChat(…)` |

AI가 처음 든 근거 중 틀린 것:
- "세션 변경은 어차피 `subscribeSession`이 스토어에 반영한다" → **틀림.** 구독은 `BroadcastChannel` 메시지인데, BroadcastChannel은 **보낸 객체 자신에게는 전달하지 않음**(HTML 표준). 같은 탭의 재발급은 이 탭 구독으로 돌아오지 않음
- "새 대화의 세션 값이 달라지지 않는다" → **틀림.** `reset()`이 `sessionId`를 `null`로 비우므로, 변이에선 `null` → `"session-1"`로 바뀜
- "요청을 보내지 않는다"는 맞음(abort된 신호의 fetch는 즉시 거절)

개발자가 "검출되지 않았다는 이유만으로 동등하다고 판단하지 말라"며 보류하고 원본·변이 차이와 실행 경로를 요구 → AI가 경로를 다시 따라가다 근거의 오류를 찾음 → 격리 worktree에서 **원본 통과 / 변이 `expected "session-1" to be null`** 로 차이를 실측.
→ `[A2] 티켓 재발급을 기다리는 사이 새 대화를 시작하면…` 추가. 확인 코드는 **실제 요구를 지키므로 유지**.
